# Дорожные карты на HDD — текущая рабочая версия (без релиза)

Файлы SCROAD01 переносятся из `dataDir/city-maps` в `speedcam-city-maps-<uid>` на HDD. Проверяются оба штатных пути: `/var/opt/hdshare` и `/mnt/share`. Разрешается штатный путь-ссылка: проверяется его реальное расположение и наиболее близкая точка монтирования. Раздел должен быть блочным и доступным для записи, не корневой файловой системой и не tmpfs. Для штатных общих папок совпадение устройства с локальным хранилищем или `/var/opt` больше не является отказом: приложение и системный помощник могут видеть разные пространства монтирования. Для неожиданных ссылок на другие папки того же раздела сохраняется отказ, кроме отдельной точки монтирования. Символические ссылки вместо папки карт не принимаются.

Совпадение раздела отражается в JSON как `attempts[].sameDevice`. Это не доказательство наличия отдельного физического HDD: расширяется программный лимит общей папки, а фактический доступный объём всегда ограничен результатом `df` с резервом. Исправление требуется и в приложении, и в системном помощнике звукового компонента. Оба пути, ведущие к одной папке, теперь показывают одинаковую причину отказа помощника, а не ошибку на одном и «диск обнаружен» на другом. Проверено на Node 8 в моделируемых условиях; на автомобиле пока не проверено.

`installed.json`, каталог карт, база камер, настройки и звук остаются в прежней папке. Выбранный путь сохраняется в `hdd-location.json`. Повторный запуск не переключается на другой диск, если прежний недоступен. Старые записи `_storage: hdd` без указателя продолжают искать прежнее хранилище. При отказе сохраняется работа с локальными картами.

Сначала приложение пытается создать свою папку и записать пробный файл. Только при EACCES/EPERM запрашивается системный помощник через существующий локальный сокет звукового компонента. Помощник сам определяет единственный UID установленного SpeedCAM по реестру OAP и package.json; клиент не передаёт владельца или произвольный путь. Он создаёт только фиксированную папку SpeedCAM с правами 0700. Использует открытые дескрипторы каталогов и O_NOFOLLOW, не меняет права общего каталога, не монтирует диск, не копирует и не удаляет карты. Непустая папка root или папка другого владельца отвергается. Подготовка выполняется в отдельном процессе с ограничением времени, чтобы fsync HDD не блокировал звуковой цикл. После ответа приложение повторно проверяет диск и возможность записи.

Для этой возможности требуется обновлённый звуковой компонент с `mapStorageProtocol: 1`; при старом компоненте или отказе помощника показывается конкретная причина, перенос не объявляется успешным. Рабочие режимы аудио не изменены. Локальный проверочный пакет собран без изменения номера версии и не опубликован.

В меню карт добавлена кнопка «Диагностика HDD»: оба пути, причина отказа, выбранная папка, способ доступа, ошибка переноса и последнее измерение свободного места. Есть повторная проверка, управление касанием и джойстиком, русский/английский текст. Та же диагностика включена в скачиваемый на телефон JSON, поле `mapStorage`. Недоступность HDD сама по себе не блокирует контроль камер.

При первом обнаружении HDD приложение показывает диалог до копирования. «Продолжить» запускает перенос, «Позже» откладывает его до следующего открытия приложения после перезапуска. Решение о начале сохраняется в `hdd-transfer.json`; прерванный начатый перенос затем продолжается автоматически. После полного переноса появляется отдельный диалог с количеством проверенных карт. Частичная ошибка не объявляется успехом. Итоговое окно сохраняется до подтверждения и не повторяется после закрытия. Пустое хранилище получает сообщение о готовности HDD, без заявления о перенесённых файлах.

Перенос выполняется асинхронно, по одному файлу. Проверяются размер, SHA-256,
формат, индекс, идентификатор и ревизия. Потоковая копия в `.migrating` ограничена
128 КиБ на блок. После fsync, повторной проверки и переименования на HDD запись
реестра сохраняется атомарно. Исходный файл удаляется только после этого.
Повторный запуск использует оставшуюся проверенную копию, если процесс оборвался
между копированием и фиксацией реестра. Неполный файл не становится установленной
картой. Ошибка копирования или фиксации сохраняет исходник.

Перед записью свободное место проверяется `df -Pk`; дополнительно оставляется
64 МиБ. Ограничение отдельного файла остаётся 64 МиБ. Лимит набора карт на HDD увеличен до 4 ГиБ; для локального хранилища сохранены 128 МиБ. Лимиты считаются отдельно, а свободное место проверяется перед каждой записью.
При отсутствии HDD, прав записи, сведений о свободном месте или места перенос
не завершается; новые загрузки могут использовать прежнюю папку. Если HDD
исчезает прямо во время загрузки, операция завершается ошибкой без замены старой
карты; следующая попытка может загрузить её локально.

Диск повторно проверяется каждые 30 секунд, в том числе без GPS. Обнаружение
отключения при отображении кэшируется не более секунды; перед изменением файлов
и удалением исходника проверка принудительно обновляется. При исчезновении HDD
после завершённого переноса дорожные карты на нём недоступны до подключения
или повторной загрузки во внутреннюю память. Записи в списке не теряются;
удаление недоступной HDD-карты не объявляется успешным. Локальные карты и
независимый контроль камер продолжают работать. Автоматически скачивать дубликаты
в фоне приложение не будет.

В меню карт отображается текущий лимит HDD либо внутреннего хранилища. Диалоги переведены на русский и английский; доступны касанием и джойстиком, в GPU и PNG. Возврат к старому приложению
не выполняет обратный перенос; старая версия не знает расположения HDD-карт.

Проверки: `tests/city-map-hdd.test.js`, `tests/city-map-hdd-package.test.js`,
прежние тесты установки, обновления, удаления, выбора пересекающихся регионов,
группировки и управления картами. Используется Node.js 8.17.0. Проверка на
физическом HDD MGU и после сна автомобиля не выполнялась.
