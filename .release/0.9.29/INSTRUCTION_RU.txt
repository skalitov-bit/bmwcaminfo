SpeedCAM 0.9.29 — инструкция к релизу

Добавлено
1. В установочный пакет передаётся mguAppStartType=autostart. Совместимый
   установщик mgu-store регистрирует запуск приложения вместе с платформой
   и восстановление остановленного процесса. Это не отдельный root-сервис.
2. Настройки → Уведомления:
   — Автозапуск контроля: включён / после открытия SpeedCAM.
   — Центральный дисплей: в приложении и в фоне / только в приложении / выключен.
   — Без дубля на Радаре: включено / выключено.
   Все три настройки доступны касанием и джойстиком, сохраняются штатным
   хранилищем приложения. По умолчанию автоконтроль и фоновый показ включены,
   дублирование на открытой вкладке Радар отключено.
3. Баннер внутри приложения доступен на всех вкладках. Исключение Радар
   учитывает именно видимость приложения, а не только последнюю вкладку.
4. Проверка свежести GPS и закрытие устаревших баннеров выполняются и в фоне.
   Фоновая работа не перерисовывает скрытую страницу карты.

Что означает отключение автозапуска контроля
Сам процесс остаётся в автозапуске платформы, иначе он не смог бы прочитать
сохранённую настройку. При выключенном автоконтроле до первого ручного открытия
SpeedCAM в текущем запуске процесса предупреждения не формируются. После
ручного открытия контроль продолжает работать и после выхода на другие экраны.
После перезапуска процесса вновь требуется ручное открытие.

Статус фонового системного баннера — экспериментальный
Подготовлен отдельный RHMI popUp с изображением, без открытия главной страницы
SpeedCAM и без захвата джойстика. Использованы документированные имена контейнера,
шаблона и свойства Timeout. Сочетание графического шаблона с popUp и вызовом
openState/closeState ещё не проверено против SDK конкретного MGU.
Доступа к автомобилю и его SDK при разработке не было.
Нельзя считать доказанными появление окна поверх штатного экрана, его размеры,
тайм-аут, приоритет, совместимость с навигацией/CarPlay и автозапуск после сна.
Фоновый системный баннер остаётся экспериментальной функцией этого релиза.

Программная логика показа
Внутри приложения используется встроенный баннер, в фоне — отдельный popUp.
Запросы и изображения отправляются последовательно; очередь не накапливается.
Системное окно запрашивается на один подход к камере, программно ограничено
3,5 секундами, не открывается снова после закрытия пользователем в том же подходе.
Потеря свежего GPS, отключение вывода и возвращение в приложение закрывают popUp.
Ошибка системного канала не отключает голос и вывод на HUD/приборную панель.
Успешный возврат API обозначается как «запрошен», а не «показ подтверждён».
Подтверждение требует события видимости от HMI. Физическую видимость проверяют
на самом центральном дисплее.

Проверено на компьютере
Метаданные обоих архивов, настройки и согласованность XML/JSON.
Политика запуска и выбора экрана, скрытый/видимый Радар, отключение вывода,
истечение времени, закрытие пользователем, поздние ответы и ошибки HMI.
Изображение и операции ресурсов проверены с подставным HMI.
Настройки проверены программными тестами касания/джойстика и открыты в эмуляторе.
Подробные результаты находятся в TEST-RESULTS.json.
Эмулятор не воспроизводит системные окна BMW и показывает «Фоновый баннер:
недоступен». Это ожидаемое ограничение эмулятора, а не тест успешного показа.

Проверка на MGU, когда он будет доступен
1. Уточнить поддержку mguAppStartType установленной версией mgu-store.
2. Проверить SDK popUp/openState и загрузку описания интерфейса до использования
   экспериментальной сборки в регулярных поездках. Сохранить предыдущий пакет.
3. После установки и полного запуска MGU не открывать SpeedCAM: проверить,
   что процесс запущен и получает свежие GPS-данные.
4. На штатном экране проверить баннер и его исчезновение, затем на Радаре —
   отсутствие дубля. Проверить каждый режим переключателя центрального дисплея.
5. Проверить восстановление после сна, перезапуска платформы и потери GPS.
   Не останавливать штатные процессы MGU принудительно ради проверки.
6. Для диагностики использовать строки CENTRAL_POPUP_* и WARNING в журнале
   SpeedCAM; не считать CENTRAL_POPUP_REQUESTED подтверждением показа.

Отдельные голосовые уведомления Стрелки и Автодории
Версия 0.9.29 включает выбор голоса по camera_model.
— Стрелка: «Внимание, впереди комплекс Стрелка».
— Автодория: «Внимание, впереди комплекс Автодория».
— Автодория с подтверждённым кодом контроля средней скорости:
  «Внимание, впереди Автодория. Контроль средней скорости».
Для второй стадии предусмотрены соответствующие записи «через двести метров».
Вторую стадию формирует существующая логика локальных дорожных камер; для
гибридной базы новые повторы и расстояния не добавлены.
Муляжи, неизвестные модели и названия только в адресе/описании не выбирают
специальную запись. Режимы голоса (всегда / при превышении / выключен),
дистанции, очередь и отмена устаревшего сообщения сохранены.

Для этих записей нужны оба обновления: приложение 0.9.29 и звуковой сервис
bmwcaminfo-voice@0.1.10.tgz. Сервис устанавливается как tool через совместимый
установщик MGU Store/mgu-deploy, приложение — своим MGU или TGZ пакетом.
Не импортируйте архив сервиса как базу камер. Если сервис старый и явно
отклоняет новый файл, приложение использует прежнее обычное предупреждение.
При отсутствии сервиса звука не будет, как и прежде.

Файлы аудио находятся в папке audio. Записи синтезированы голосом
ru-RU-SvetlanaNeural и нормализованы как в прежнем звуковом сервисе.
Все восемь файлов декодируются без ошибок; длительность аудиомаршрута
рассчитывается по длине записи с запасом. Проверены выбор на текущей базе,
совместимость со старым сервисом, отмена и отсутствие повторов при тайм-ауте.
Реальные BMW MediaPlayer и громкость в автомобиле не проверялись: MGU недоступен.

Пересборка звукового сервиса из исходников:
python bmw-speed-camera-warning/tools/pack_voice.py --out release
Готовые записи уже включены в архив исходников. Генерация новых записей:
python -m pip install edge-tts gTTS imageio-ffmpeg mutagen
python bmw-speed-camera-warning/tools/build_voice_assets.py
